# Juego-UNO-Java 🎴

¡Bienvenido al repositorio de **Juego-UNO-Java**! Este proyecto consiste en el desarrollo progresivo de un simulador del clásico juego de cartas UNO implementado en Java. El desarrollo se ha llevado a cabo de manera estructurada en cinco etapas o entregas principales, aplicando principios de ingeniería de software, refactorización y pruebas unitarias.

---

## 🚀 Evolución del Proyecto (Historial de Versiones)

A lo largo del ciclo de vida del desarrollo, el proyecto ha evolucionado desde una versión básica en consola hasta convertirse en una aplicación con interfaz gráfica e integración de reglas complejas.

### 🔹 Versión 1 (V1) - Base del Juego
* **Objetivo:** Creación de la lógica inicial y estructura fundamental.
* **Características:** Implementación del mazo básico que incluye únicamente **cartas numéricas**.
* **Entregables:** Código fuente base y primer modelado del sistema.

### 🔹 Versión 2 (V2) - Dinámicas Especiales
* **Objetivo:** Expandir las reglas y mecánicas del juego original.
* **Características:** Se integraron las **cartas especiales** (Reversa, Salta, Toma 2, Comodines), añadiendo la lógica y el dinamismo característicos del juego real.

### 🔹 Versión 3 (V3) - Refactorización de Código
* **Objetivo:** Mejorar la calidad interna del software sin alterar su comportamiento externo.
* **Características:** Limpieza de código, optimización de métodos, aplicación de buenas prácticas de programación y mejora de la modularidad.

### 🔹 Versión 4 (V4) - Pruebas y Gestión de Descartes
* **Objetivo:** Garantizar la estabilidad del sistema e implementar mejoras lógicas de flujo.
* **Características:** * Ejecución y gestión de **pruebas técnicas** utilizando el entorno **NetBeans**.
  * Implementación de la **pila de reciclaje** para las cartas desechadas, optimizando la reutilización del mazo cuando este se agota.

### 🔹 Versión 5 (V5) - Interfaz Gráfica (Entrega Final)
* **Objetivo:** Mejorar la experiencia del usuario (UX/UI).
* **Características:** Migración del juego del entorno de consola tradicional a una **interfaz gráfica de usuario (GUI) completamente interactiva y funcional**.

---

## 📊 Arquitectura y Documentación (UML)

Un pilar fundamental de este proyecto ha sido la trazabilidad y el diseño de software. Por ello, **en cada una de las entregas se modificaron y actualizaron los diagramas UML** para reflejar con precisión la arquitectura, las nuevas clases, herencias y relaciones del sistema a medida que el juego crecía en complejidad.

Puedes encontrar la documentación y los diagramas correspondientes organizados dentro de las carpetas de cada versión (`/V1`, `/V2`, etc.).
